{{ .Title }}

From an empty directory to Uptime Kuma, a self-hosted monitoring tool, on a kind cluster on your machine: install Kapitan, fetch the uptime-kuma recipe pinned by version and digest, verify it, compile it and apply the manifests. The steps take about five minutes, most of it waiting for the image and the first readiness probe.

{{ if or (not $r.latest) $r.blocked }}

The uptime-kuma recipe has no version this page can pin right now. Its recipe page says why.

{{ else }}

What you need

Docker, kind, kubectl, uv and the GitHub CLI gh, logged in with gh auth login for the verify step.

1. Create a kind cluster

kind runs a Kubernetes node as a container and points kubectl at it.

{{ partial "snippet.html" (dict "id" "cluster" "label" "cluster command" "text" "kind create cluster --name quickstart-uptime-kuma") }}

2. Install Kapitan

This installs Kapitan 0.36.3 as a uv tool with the pins of the consumer docs. omegaconf stays at 2.4.0.dev4 because later releases removed ListMergeMode, which Kapitan imports, and oras lets Kapitan fetch OCI artifacts. Python 3.13 is pinned because Kapitan requires regex below 2025, which has no wheels for newer Pythons, so uv would build it from source. uv puts kapitan into ~/.local/bin.

{{ partial "snippet.html" (dict "id" "install" "label" "install command" "text" "uv tool install --python 3.13 --with omegaconf==2.4.0.dev4 --with oras 'kapitan[omegaconf,reclass-rs]==0.36.3'") }}

3. Write the project

This creates the project directory and selects the omegaconf inventory backend:

{{ partial "snippet.html" (dict "id" "project" "label" "project commands" "text" "mkdir -p uptime-kuma/fetch/targets uptime-kuma/inventory/targets\ncd uptime-kuma\ncat > .kapitan <<'EOF'\nglobal:\n inventory-backend: omegaconf\nEOF") }}

The fetch inventory pins the recipe by version {{ $r.latest.version }} and digest. It is a separate inventory because Kapitan reads the inventory before it fetches, so a class cannot be fetched by the inventory that includes it:

{{ partial "snippet.html" (dict "id" "fetch" "label" "fetch inventory" "text" (printf "cat > fetch/targets/recipes.yml <<'EOF'\n%s\nEOF" $r.fetch) "event" "copy-fetch-inventory/quickstart") }}

The target includes the recipe as a class and sets the namespace and the target's name, which is also its output directory under compiled/:

{{ partial "snippet.html" (dict "id" "target" "label" "target" "text" (printf "cat > inventory/targets/uptime-kuma.yml <<'EOF'\n%s\nEOF" $r.include)) }}

4. Verify the recipe

Kapitan's --fetch checks neither the digest nor the attestation. This checks that kadet-hub's release workflow built the recipe at this digest and signed its provenance. On a terminal gh prints what it verified; in a script only the exit status tells.

{{ partial "snippet.html" (dict "id" "verify" "label" "verify command" "text" $r.verify "event" "copy-verify/quickstart") }}

It does not check that the index still lists the digest, nor the generator the recipe pins. Verifying a recipe by hand does both and pulls exactly the verified digest.

5. Compile

The first command fetches the recipe into inventory/classes/recipes/uptime-kuma and then exits with status 1 and No such file or directory: .../compiled, because the fetch target compiles nothing. The second fetches the kubernetes generator the recipe pins into lib/kubernetes and writes a StatefulSet and a Service to compiled/uptime-kuma/manifests/. It warns that the container sets no resource requests; a target sets them under components.uptime-kuma.resources.

{{ with $r.included }}

Version {{ $r.latest.version }} includes {{ . }}. Kapitan's --fetch reads no index, so pull the included recipes by digest before the second command:

{{ partial "snippet.html" (dict "id" "pull" "label" "pull commands" "text" $r.pull) }} {{ end }}{{ partial "snippet.html" (dict "id" "compile" "label" "compile commands" "text" $r.commands) }}

6. Apply

The recipe renders no Namespace, so the first command creates it. rollout status waits until the pod is ready. Its readiness probe runs every 60 seconds, so this takes a minute or two after the image is pulled.

{{ partial "snippet.html" (dict "id" "apply" "label" "apply commands" "text" "kubectl create namespace uptime-kuma\nkubectl apply -R -f compiled/uptime-kuma\nkubectl -n uptime-kuma rollout status statefulset/uptime-kuma --timeout=5m") }}

7. Open Uptime Kuma

This forwards port 3001 on your machine to the Service until you stop it with Ctrl+C. Open http://localhost:3001. Uptime Kuma asks for an admin account on the first visit, without a login, and anyone who reaches the Service can claim it, so create the account before you expose the Service.

{{ partial "snippet.html" (dict "id" "open" "label" "port-forward command" "text" "kubectl -n uptime-kuma port-forward service/uptime-kuma 3001:3001") }}

Clean up

This deletes the cluster and everything in it.

{{ partial "snippet.html" (dict "id" "cleanup" "label" "cleanup command" "text" "kind delete cluster --name quickstart-uptime-kuma") }}
